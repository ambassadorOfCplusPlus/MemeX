## 1. Что крупные компании РЕАЛЬНО используют в проде

### DeepSeek
- **MLA (Multi-head Latent Attention)** — низкоранговое сжатие K/V в общий латент, кэшируется только латент → KV-кэш меньше на ~порядок. Прод с V3. *Прямой донор нашего сжатого хвоста.*
- **DSA (V3.2)** — «lightning indexer»: крошечная сеть оценивает, на какие токены смотреть каждому query, top-k отбор → почти линейная цена длинного контекста при паритете качества.
- **Fine-grained MoE**: 256 маленьких экспертов + 1 общий (shared), активно ~5.5% параметров.
- **MTP (multi-token prediction)** — предсказание 2–4 токенов за проход, головы внутри чекпоинта; в V4 даёт 2–3× ускорение инференса.
- **Engram (янв 2026, код открыт)** — детерминированная N-gram lookup-память: таблицы знаний лежат в обычной RAM и префетчатся без оверхеда (адрес зависит только от ID токенов). +13 пунктов needle-in-haystack. «Вторая ось разреженности» рядом с MoE.
- FP8-обучение, EPLB (динамическая балансировка экспертов по нагрузке, код открыт).

### Moonshot / Kimi
- **Kimi Linear / K3**: гибрид KDA (Gated DeltaNet с поканальными forget-гейтами) : полное MLA = 3:1 → −75% KV-кэша, ~6× декод на 1M контексте. Первый гибрид, побивший полное внимание при честном сравнении.
- **K3 (июль 2026)**: NoPE везде (без RoPE вообще), Attention Residuals, **LatentMoE** (эксперты работают в суженном латенте — 896 экспертов, 16 активных), MXFP4, MuonClip.

### Alibaba / Qwen
- **Qwen3-Next / 3.5**: гибрид Gated DeltaNet : полное внимание = 3:1, ультра-разреженный MoE (512 экспертов, ~3B активных из 80B). Кернелы GDN — в открытой библиотеке fla.

### Google
- **Gemma 3 (прод)**: 5:1 локальное (окно 1024) : глобальное внимание → KV-оверхед с ~60% до <15%.
- **Titans / Atlas / Nested Learning (исследования)**: нейронная долговременная память, обновляемая на инференсе градиентом по сигналу «удивления»; забывание через learned decay. Официального кода нет — статус «наблюдать».
- **Infini-attention**: локальное окно + компрессивная линейная память в одном блоке. Публичная репродукция (HuggingFace) провалилась — гейт не сходился. Наш v2-дизайн избегает гейта в принципе.
- Патенты: внешняя память нейросетей (US12099928B2 и семейство), базовый патент трансформера, MoE-слой Шазира (US10719761B2).

### Microsoft
- **YOCO**: KV-кэш строится один раз и переиспользуется второй половиной слоёв через cross-attention → экономия ~L×. *Донор нашего «общего хвоста на все слои».*
- **Phi-4-mini-flash / SambaY (прод)**: Mamba + оконное внимание + один полный слой + Gated Memory Units → 10× декод на 3.8B.
- **BitNet b1.58**: тернарные веса {-1,0,+1}, открытая 2B-модель, инференс-стек bitnet.cpp (CPU-friendly). Паритет с FP16 — только от ~3B.
- **LoLCATs-родственное**: (HazyResearch/Stanford) — конверсия готовых моделей в линейное внимание за 40M токенов.

### Meta
- **Llama 4**: MoE + iRoPE (3 слоя RoPE с чанк-вниманием 8K : 1 слой NoPE с полным вниманием), заявка на 10M контекста.
- **Memory Layers at Scale (код открыт)**: обучаемые product-key lookup-таблицы вместо части FFN — параметры почти без FLOPs; 1.3B с памятью ≈ dense 2× компьюта. Таблицы можно держать в RAM.
- **V-JEPA 2 (код и веса открыты)**: self-supervised видео-энкодер мира; заморожен + проектор → уже прикручивался к LLM (LLaVA-стиль), SOTA VidQA до 8B.
- **BLT (байтовый трансформер)**, **Mixture-of-Transformers** (модальные башни с общим вниманием, качество Chameleon за 55.8% FLOPs), **LayerSkip** (early-exit + самоспекулятивный декод), **ParetoQ** (рецепт QAT: 90% обучения FP, последние 10% — квантизация; тернарная 600M бьёт прежние тернарные 3B).

### OpenAI (единственное реальное раскрытие — gpt-oss)
- Чередование полного и **128-токенного** оконного внимания, GQA, 128 экспертов top-4, **learned attention sinks** (обучаемый bias в знаменателе softmax — «голова может смотреть в никуда»), YaRN до 131k, MXFP4 — 117B влезает в одну 80GB GPU.
- Закрытые модели: архитектура не раскрыта; продуктово — 400K контекст, авто-компакция в Codex.

### Anthropic
- Архитектурных публикаций нет. Продуктово: 1M контекст, **context editing + memory tool** (сент 2025: −84% токенов в 100-ходовых агентных сценариях, +39% качества) — то есть агентная память как у нашего harness-слоя, подтверждена как рабочая. Патенты — про агентную автоматизацию UI, не про архитектуру. Проверенных «сливов» архитектур не существует.

### Прод-стек инференса (все крупные)
- PagedAttention (vLLM, открытая академическая работа), continuous batching, **prefill/decode disaggregation** (раздельные ноды под префилл и декод; MTP+chunked prefill −70–80% TTFT), FP8 веса, FlashAttention. Итог типового стека: 5–8× цена/токен против наивного FP16.
- **Muon вытеснил AdamW**: GLM-5, Kimi K2 (MuonClip), DeepSeek-V4, K3 (Per-Head Muon). Нативен в PyTorch 2.9.
- Спекулятивный декод: EAGLE-3 (до 6.5×), MTP-головы внутри чекпоинта.
- KV-тиринг: NVIDIA Dynamo, патенты Intel (вытеснение токенов, US20250036876A1), IBM (префикс-кэш), HPE (NIC-оффлоад KV, US12346252B1).

**Консенсус-стек 2025–26 «в разы меньше памяти без потери качества»:** MLA (или GQA+SWA) + гибрид линейное:полное 3:1 + обучаемое разреженное внимание на полных слоях + мелкозернистый MoE с shared-экспертом + FP8/FP4 + (новая ось) lookup-память Engram/Memory Layers. Единственный откат: MiniMax M2 вернулся к полному вниманию (multi-hop страдал) — но Kimi Linear показал обратное при честном сравнении.

## 2. Гибридное внимание — полный список изученного

| Система | Схема | Результат |
|---|---|---|

| gpt-oss | полное/окно-128 1:1 + sinks | 117B на одной 80GB |
| Samba (MS) | Mamba+SWA+MLP, проверен на 421M/1.3B/3.8B | обучен на 4K → идеальный passkey на 256K после 500 шагов файнтюна; ×3.64 декод |
| Jamba (AI21) | 7:1 Mamba:attention + MoE | 256K контекст с 4GB KV на 52B |
| Zamba/Zamba2 | Mamba + один общий attention-блок | работает на 1.2B/2.7B |
| Nemotron-H (NVIDIA) | ~8% attention-слоёв | паритет с трансформером, ×3 инференс |
| Hymba (NVIDIA, 1.5B) | параллельные attention+Mamba головы в слое + 128 learned meta-токенов | SOTA sub-2B на релизе |
| Granite 4.0 (IBM) | Mamba-2:attention 9:1, NoPE | −70% памяти long-context |
| MiniMax-01 → M2 | 7:1 lightning:softmax → откат к полному | предостережение: multi-hop |
| Kimi Linear | KDA:MLA 3:1 | −75% KV, ×3.98 на 128k, бьёт полное |
| NSA (DeepSeek) | сжатые блоки + top-k блоков + окно, обучаемое | best paper ACL 2025 |
| MoBA (Moonshot) | MoE-роутинг блоков внимания | в проде Kimi |
| YOCO (MS) | один KV-кэш на все слои второй половины | ~L× экономия, needle на 1M |

**Теория (Zoology/Based, HazyResearch):** 82% разрыва линейного и полного внимания — это associative recall; крошечная добавка точного внимания (окно) закрывает ~97% разрыва. → Научное обоснование нашего точного окна.

**Провалы, которые надо знать:**
1. Точный recall не живёт в сжатом состоянии — нужен точный путь (наше окно+блокнот).
2. Multi-hop при масштабировании (MiniMax M2).
3. Гейты локальное/сжатое не сходятся (Infini-attention) — у нас гейта нет, один softmax.
4. Жёсткое вытеснение необратимо (H2O/SnapKV) — у нас вытеснение = понижение в хвост.
5. Perplexity ≠ recall: тестировать MQAR/needle/RULER всегда.

## 3. Компрессивная / O(1) память
- **Compressive Transformer (2019)** — предок: старые активации сжимаются 3–4× в FIFO-память.
- **Memorizing Transformers** — kNN-поиск по кэшу 262K пар (k,v): 1B с памятью ≈ 8B без.
- **RMT** — memory-токены между сегментами: GPT-2 137M решает BABILong до 10–50M токенов. Лучшее доказательство «малая модель + крошечная память = экстремальный recall».
- **Titans/Atlas/TTT** — память = маленькая сеть, обучаемая на инференсе; «удивление» = норма градиента. Кода нет, репродукции сырые.
- **Gist-токены** — сжатие промпта 26× в несколько токенов.
- **H2O/SnapKV/StreamingLLM** — вытеснение KV по важности; работает, но потерянное не вернуть.

## 4. Конверсия готовых моделей (вместо предобучения)
- **LoLCATs**: (1) линейное+оконное внимание учится имитировать softmax (MSE), (2) LoRA латает остаток. 40M токенов, часы на 1 GPU для 7B, <0.2% параметров. → Наш путь для быстрого старта и источник идеи дистилляции сжатия хвоста.
- **MambaInLlama**: замена 50–75% слоёв на Mamba с инициализацией из attention-проекций; урок — оставлять ≥25% полных слоёв.
- SUPRA, Hedgehog, RADLADS (~$100 за конверсию).

## 5. MoE-оффлоадинг — полный список систем
- **Факты-рамки**: PCIe 4.0 ≈ 25 ГБ/с реально; перекачка экспертов = 85–94% латентности наивного оффлоадинга; эксперт Mixtral fp16 = 336 МБ ≈ 10–14 мс.
- **mixtral-offloading**: LRU (hit ~80% при k=4) + спекулятивный префетч гейтом прошлого слоя (recall ~70%); 2–3 ток/с на 12–16GB GPU. Простейший код — точка старта.
- **MoE-Infinity**: матрица активаций per-request, приоритеты префетча/вытеснения обновляются онлайн; 3.1–16.7× vs vLLM. Ближайший аналог нашей идеи. Apache-2.0.
- **Fiddler**: холодный эксперт считается НА CPU (активация — килобайты) вместо перекачки; fp16 Mixtral >3 ток/с на 24GB.
- **ktransformers**: инженерная версия того же: DeepSeek-R1 671B Q4 на 4090+512GB RAM: 286 ток/с префилл, ~14 ток/с декод. Размещение статическое.
- **llama.cpp `--n-cpu-moe`**: статический базлайн, который надо бить (Qwen3-30B-A3B: 50–60 ток/с на 12GB).
- **Fate**: вход гейта слоя i предсказывает экспертов i+1 на ~97% (training-free); hit 99% с shallow-favoring кэшем.
- **HOBBIT**: при промахе грузим 2–4-битную копию сразу, полную фоном; до 9.9× на edge.
- **AdapMoE**: пропуск маргинальных экспертов (−25% активаций без потерь) + DP-аллокация размера кэша по слоям = автоподстройка под VRAM.
- **ProMoE, SiDA-MoE, fMoE, BuddyMoE** (подмена похожим резидентным экспертом), **MoE-SpeQ** (драфт-модель предсказывает будущих экспертов), **ExpertFlow** (адаптивный горизонт префетча), **Pre-gated MoE** (гейт слоя N выбирает экспертов N+1 — требует переобучения).
- **EPLB (DeepSeek) / vLLM RFC #38256**: пере-балансировка размещения по статистике каждые N шагов асинхронно; LFRU-скоринг `freq/(clock−last_access+1)`, hit 97–100% в прод-данных.
- **Критика (arXiv:2608.07911)**: trace-replay завышает LRU-политики на 27–29%; LFRU — лучшая честная политика; разрыв до оптимума Белади в основном непреодолим.
- **Свободные ниши** (проверено): гетерогенные эксперты + knapsack-вытеснение; чистый авто-тюнинг под железо для локального инференса; исследование гранулярности пере-рейтинга «каждые N токенов».

## 6. Молодые технологии — топ-10 по (эффект × реализуемость соло)
1. **Muon + modded-nanogpt стек** — до ~10× wall-clock против ванильного nanoGPT; копипаст-зрелость.
2. **Gated DeltaNet (fla)** — KV не растёт; прод-кернелы; проверен в Qwen3-Next.
3. **Mixture-of-Recursions** — общий стек слоёв рекурсивно, у каждого токена своя глубина; ~⅓ уникальных параметров, ×2 throughput; код с конфигами от 135M.
4. **ParetoQ QAT** — тернарность в последние 10% обучения; ×8–16 сжатие инференса.
5. **Memory Layers (Meta)** — ёмкость 2×-компьют модели при тех же FLOPs; таблицы в RAM.
6. **Engram (DeepSeek)** — N-gram lookup с префетчем из RAM; реализуем за выходные; выше всех upside среди молодых.
7. **RWKV-7** — константная память, полный открытый стек обучения, модели от 0.19B.
8. **LayerSkip** — early-exit + самоспекулятивный декод, 1.5–2×; в HF/torchtune.
9. **muP + MiniPLM-дистилляция + SmolLM/TinyStories данные** — «больше качества на токен», нулевой риск.
10. **NVFP4-обучение** — ×2 память/×2–3 компьют, но Blackwell-only и капризно; отложить.
- Watch-list: Mamba-3 (ICLR 2026, полсостояния Mamba-2 — ждать кернелов в fla), Titans/Hope, TTT, диффузионные LLM (LLaDA/Mercury: 1100 ток/с, но памяти не экономят), BLT, COCONUT (латентный CoT — обучался на GPT-2 масштабе!), EAGLE-3.

## 7. Мультимодальность (фото/видео/физика)
- **Паттерн для нас — late-fusion адаптеры на замороженном бэкбоне**; валидировано X-InstructBLIP (независимые адаптеры image/video/audio/3D на один замороженный LLM, эмерджентный кросс-модальный резонинг без совместного обучения).
- **Фото**: SigLIP + pixel-shuffle + MLP-проектор. nanoVLM-222M: ~6 часов одной H100, 1.7M примеров, паритет со SmolVLM-256M. Данные открыты (the_cauldron). Q-Former — сильнейший «всё заморожено», но капризен; Flamingo-гейты (α=0 на старте) — гарантия нерегрессии текста.
- **Видео**: главная проблема — бюджет токенов (256–729/кадр). Рецепты Apollo (CVPR 2025): fps-сэмплинг > равномерного, Perceiver Resampler — лучший компрессор, timestamp-токены +2–3%; выводы переносятся с 2–4B проксей. SmolVLM2-500M ≈ 2.2B по качеству видео. Данные открыты (LLaVA-Video-178K, FineVideo).
- **Физика**: честно — «понимания физики» в языке нет ни у кого: IntPhys 2 — все у случайности (GPT-4o, Gemini, V-JEPA 2); PhysBench: средний VLM ~40%. Что работает: замороженный V-JEPA 2 + surprise-метрика (87.2 на IntPhys-1, нарушение ожиданий) и V-JEPA 2 как видеоэнкодер для LLM (Meta делала, код открыт). Реалистичная цель: выше случайного QA + отличный детектор аномалий.
- Cosmos-Reason1-7B (NVIDIA) — сильнейший открытый «физический» VLM; его данные пригодны для дистилляции в малую модель.

## Путь к 40 ток/с: что даёт внешний поиск (август 2026)

Цель поставлена как «40 ток/с без потерь качества», и второе условие важнее первого, потому
что оно отсекает почти всё. Строго без потерь работает **ровно один** приём —
спекулятивное декодирование: оно математически сохраняет распределение целевой модели, и
токены статистически неотличимы от обычной генерации. Всё остальное стоит от 0.16% до
единиц процентов. Поэтому дальше цена указана всегда, а не только выигрыш.

### Идея про плотную оптимизацию оказалась главной находкой

Наблюдение простое и верное: после выбора экспертов проход плотный — 3.3B активных
параметров, — и к нему применимо всё, что придумано для плотных моделей. Самый сильный
приём из этого пласта не квантование, а **разреженность активаций**: она уменьшает
читаемые байты, вообще не меняя веса.

**TEAL** (ICLR'25) даёт 40–50% разреженности по всей модели без дообучения, магнитудным
порогом на входах всех трёх матриц, и заявляет 1.53–1.8× на однопакетной генерации — ровно
наш режим, потому что он ограничен памятью. **CATS** делает то же скромнее (~25%
по модели, порог на выходе гейта), зато проще и на 50% разреженности внутри MLP теряет
1–2%.

Что важнее всего: есть работа, которая **измерила это именно на Qwen3-30B-A3B** («Universal
Properties of Activation Sparsity», NeurIPS'25). Вывод: эксперты MoE достигают
разреженности активаций, сопоставимой с плотными моделями, а отдельные эксперты внутри слоя
показывают заметно более высокую, выбросовую разреженность. «Критическая разреженность» у
них определена как максимальная при падении качества не более 1%. То есть приём применим к
нашей модели не по аналогии, а по замеру — хотя сами авторы честно пишут, что времени не
мерили, только терпимость к разреженности.

#### Препятствие, которое надо обойти именно у нас

Разреженность входа означает пропуск элементов внутри строки весовой матрицы. У нас веса
блочно-квантованы (Q8_0, блок 32), и пропустить половину элементов строки нельзя — блок
читается целиком. Случайная 50-процентная разреженность не даёт ни одного целого
сэкономленного блока.

Обходится это тем, что мы сами делаем блоб экспертов. Схема CATS даёт чистый пропуск
**строк**, а не элементов: считаем гейт полностью (это 1/3 байт), порогом отбираем живые
промежуточные единицы, и читаем только их строки в `up`, а в `down` — только их столбцы.
Столбцы `down` становятся строками, если хранить его транспонированным, а формат блоба наш.
Итого экономия = 2/3 × разреженность: при 50% это 33% байт экспертов, то есть 1.5×, и всё
чтение остаётся непрерывным.

Альтернатива — **блочно-выровненная разреженность**: порог по норме каждой группы из 32
элементов, отбрасываем группу целиком. Грубее по качеству, зато работает и на входах, и без
транспонирования. Что лучше — вопрос замера, и у нас есть трассы активаций, чтобы ответить
не гадая.

### Поворот Адамара: дешевле байты без платы за качество

Подсказку дал сам форк: у ik_llama есть флаги `-khad` и `-vhad`, «может улучшить качество KV
при сильном квантовании». За этим стоит **QuaRot** и **SpinQuant**: случайный поворот
Адамара убирает выбросы из активаций и KV, не меняя выхода модели, и делает 4-битное
квантование почти бесплатным — заявлено сохранение более 99% точности и рост перплексии
меньше 0.5 пункта.

Для внимания это особенно красиво, потому что скалярное произведение инвариантно к общему
повороту: `(Hq)·(Hk) = q·k`. Значит ключи можно поворачивать бесплатно. Для значений нужен
один обратный поворот на токен, потому что выход — взвешенная сумма: `out = Hᵗ(Σ p_j H v_j)`.

Прямое следствие для нас: **хвост Q4_0 с поворотом должен дать качество Q8_0 при вдвое
меньших байтах** — 576 против 1088 на позицию. Это самый дешёвый в реализации пункт из всего
списка, потому что наш стенд уже умеет мерить ошибку выхода внимания, а поворот это одно
матричное умножение на калибровке.

### Разреженное внимание: хвост можно не читать целиком

**Quest** (ICML'24) выбирает страницы KV по запросу: хранит поканальные минимум и максимум
ключей в каждой странице, оценивает по ним верхнюю границу скора и читает только top-k
страниц. Заявлено 2.23× на самом внимании и до 7.03× по задержке при пренебрежимой потере
точности.

Это складывается с зонами напрямую и, честно говоря, лучше нашей нынешней политики хвоста:
сейчас мы хвост сжимаем и читаем весь, а можно сжимать **и** читать десятую часть.
Метаданные дешёвые — два вектора d_kv на страницу, считаются когда страница закрывается, а у
нас страницы уже есть: блок Q8_0 из 32 позиций это ровно страница.

### Спекуляция: единственное строго бесплатное

- **MTP в llama.cpp для Qwen 3.6**: у модели свои головы предсказания нескольких токенов,
  спекуляция встроена. Замер: Qwen3.6 27B с 38 до 65 ток/с, 1.71×, без видимой потери
  качества. У нас Qwen3.6-35B-A3B уже скачан.
- **EAGLE-3**: средняя принятая длина 1.74–2.2 на серии Qwen3, сквозное ускорение 1.8–2.0×,
  и это без потери качества по построению.
- **Prompt lookup (n-граммы из промпта)**: черновик берётся из самого текста, скачивать
  нечего, «почти никогда не вредит». На коде принятая длина 1.43–1.57. Для нашего сценария с
  Qwen3-Coder это бесплатный выигрыш.

Наш прошлый замер, где спекуляция в ik оказалась отрицательной, касался внешнего черновика и
быстрых ядер, из-за которых проверочный проход стал ограничен вычислениями. MTP и n-граммы
это другая конструкция: черновик почти не стоит, а проверочный проход читает веса один раз
на несколько токенов. При длинном контексте он к тому же один раз читает KV на всю пачку —
и это ровно та статья расходов, которая у нас растёт.

### Со стороны экспертов

- **REAP** (Cerebras, 2025): одноразовое отсечение экспертов по критерию, учитывающему и
  веса роутера, и нормы активаций. При 25% отсечения падение точности **0.16%** — то есть
  практически бесплатно; при 50% сохраняется больше 96%. Прямого выигрыша в байтах на токен
  это не даёт (top-8 всё равно читается), зато уменьшает общий объём экспертов на четверть,
  а значит доля, влезающая в 3.4 ГБ VRAM, растёт с 12% до 16% — и складывается с нашим
  бонусом резидентным экспертам.
- **`-ser` в ik_llama** («fmoe/ser: basically REAP from command line») уменьшает число
  активных экспертов, например `-ser 1,6` вместо 8. Это уже прямые −25% байт на токен. Наш
  отказ от Adaptive-K опирался на плоскость распределения веса роутера, а не на замеренную
  перплексию при top-6 — и это дешёвый замер, который стоит просто сделать.
- **Fiddler** (CPU-GPU оркестровка) считает экспертов на CPU, чтобы не гонять их через шину:
  Mixtral-8x7B на 90+ ГБ весов даёт больше 3 ток/с на одной 24-гиговой карте. Наш
  одновременный счёт CPU+GPU — это то же решение, найденное независимо.
- **BuddyMoE**, **Dynamic Expert Quantization**, **OD-MoE**, **PIPO** — семейство 2025–2026
  про то же: избыточность между экспертами, динамическая битность, загрузка по требованию.

### Квантование: где предел без потерь

- **QTIP / QuIP# / AQLM / VPTQ / GLVQ**: решётчатое и векторное квантование с
  incoherence-обработкой. QTIP превосходит QuIP# и AQLM, у 2–3 бит деградация минимальна;
  GLVQ-32D на Llama2-70B при 2 битах даёт перплексию 3.36 против 3.78 у QTIP.
- **EXL3** — это QTIP в работающем виде (ExLlamaV3): почти FP16 на 6–8 битах и «высоко
  конкурентно» на 3 битах, с автоматическим распределением точности по чувствительности
  слоёв. Но декодер решётки рассчитан на тензорные ядра NVIDIA; у нас CPU без AVX-512 и
  Vulkan на RX 6500 XT, поэтому цена декодирования съест выигрыш. Практический путь для нас
  — i-кванты самого ik (IQ4_KS, IQ3_KS и родственные), которые уже калиброваны и имеют
  ядра под наше железо.
- **NVIDIA, заявка 2026**: восстановление точности без дообучения через низкоранговое
  представление в собственном подпространстве. **Институт автоматизации АН Китая, 2025–2026**:
  заявки прямо про MoE — квантование плюс динамическое отсечение экспертов по типу задачи.
  То есть обе наши главные линии патентуются прямо сейчас, независимо от нас.

### Что из высокопроизводительных движков переносится, а что нет

Не переносится главное, чем они быстры: непрерывная пакетная обработка, общие префиксы,
тензорный параллелизм — всё это про много запросов и много карт. У нас один поток и одна
слабая карта.

Переносится три вещи:
1. **Слияние ядер.** TensorRT-LLM сопоставляет шаблоны графа и подставляет заранее
   скомпилированные слитые ядра; vLLM и SGLang используют отдельные ядра. В ik уже есть
   слитые операции (`fused_rms_norm`, `fused_mul_unary`, `-fmoe` сливает up и gate) — надо
   убедиться, что мы их включаем.
2. **Переиспользование графа.** SGLang захватывает CUDA Graph на прогреве, чтобы убрать
   накладные на запуск ядер. У нас на маленьких тензорах при 48 слоях это заметно, и
   аналог — переиспользование командного буфера Vulkan.
3. **Группированные GEMM** для параллельных матричных умножений — это и есть `mul_mat_id`.

### Арифметика: достижимы ли 40 ток/с

40 ток/с это 25 мс на токен. Считаю по нашим измеренным полосам (RAM 20.1 ГБ/с, VRAM 84.6,
перекрытие 86%), базово ~2.0 ГБ активных весов и ~0.43 ГБ KV при 8k.

| множитель | на что действует | во сколько | цена качества |
|---|---|---:|---|
| разреженность активаций (CATS, 50% на up и down) | эксперты и плотная часть | ×0.67 | 1–2% |
| `-ser`, top-6 вместо top-8 | эксперты | ×0.75 | **не замерено у нас** |
| калиброванные i-кванты вместо нашей лестницы | эксперты | ×0.7 | ~1% |
| Адамар + Q4_0 в хвосте | KV | ×0.53 | <0.5 п. перплексии |
| top-k страниц (Quest) | KV | ×0.2 | «пренебрежимо» |
| MTP или n-граммы | всё | ×1.3…1.7 | **ноль, строго** |

Стек без спекуляции: эксперты 2.0 → 0.70 ГБ, плотная часть 0.4 → 0.27, KV 0.43 → 0.05.
Итого ~1.02 ГБ на токен. При 60% резидентности: VRAM 0.61/84.6 = 7.2 мс, RAM 0.41/20.1 =
20.4 мс, с перекрытием max(...)/0.86 = **23.7 мс, то есть 42 ток/с**. Спекуляция сверху даёт
запас.

Так что 40 ток/с арифметически достижимы — но **не одним приёмом, а стеком из пяти**, и
четыре из пяти стоят от 0.2% до 2% качества. Складывать пять «почти бесплатных» вещей — это
ровно тот способ, которым качество тихо уходит. Поэтому правильная форма работы: бюджет
перплексии (скажем, не более +2% суммарно), и каждый приём вносится только после замера
своей доли в этом бюджете. Единственный, который можно включить без бюджета, — спекуляция.

### Порядок, в котором это стоит делать

1. **Адамар в хвосте.** Стенд готов, цена почти нулевая, выигрыш вдвое по KV. Полдня.
2. **Спекуляция через MTP** на Qwen3.6-35B-A3B, который уже скачан. Строго бесплатно.
3. **Перплексия при top-6** — один замер, который либо даёт −25% байт экспертов, либо
   окончательно закрывает вопрос.
4. **Разреженность активаций по схеме CATS** с транспонированным `down` в нашем блобе.
   Самый большой выигрыш и самая большая работа.
5. **top-k страниц в хвосте** вместо чтения всего хвоста.
6. Флаги ik, которые могли просто не быть включены: `-fmoe`, `-ctk/-ctv q8_0`, `-ot` для
   размещения, `-ooae`. `-rtr` — с осторожностью: при гибридном CPU/GPU для MoE его
   рекомендуют не включать.

## Бюджет байт на токен, и что из него следует

Разложение проверяется само: 8.7 ток/с это 115 мс, и если сложить всё, что читается за токен,
получается 2.44 ГБ — то есть 21.2 ГБ/с, ровно наша измеренная полоса RAM. Значит мы упираемся
в память и ни во что больше, и любой приём стоит оценивать одним числом: на сколько он
уменьшает эти 2.44 ГБ.

| статья | Q6_K_XL | доля |
|---|---:|---:|
| активные эксперты (8 из 128) | 1.44 ГБ | 59% |
| веса внимания (q, k, v, o × 48 слоёв) | 0.74 ГБ | 30% |
| выходная голова (151936 × 2048) | 0.26 ГБ | 11% |

Два вывода сразу. Первый: выходная голова читается **целиком каждый токен** и стоит 11% —
её надо квантовать наравне с остальным. Второй: веса внимания весят 0.74 ГБ **на все 48
слоёв**, то есть целиком влезают в 3.8 ГБ VRAM с большим запасом. Это меняет вопрос с «что
положить на карту» на «что оставить в RAM».

### Куда это приводит

| шаг | байт/токен | ток/с |
|---|---:|---:|
| сейчас, Q6_K_XL | 2.44 ГБ | 8.7 |
| эксперты + attn_q + attn_output в IQ4_XS | 1.70 ГБ | 12.5 |
| выходная голова тоже в IQ4_XS | 1.61 ГБ | 13.2 |
| 11 целых слоёв в VRAM (влезают при IQ4) | — | 13.8 |
| эксперты в IQ3 вместо IQ4 | 1.32 ГБ | ~16 |
| 16 целых слоёв в VRAM (влезают при IQ3) | — | ~21 |
| внимание и голова целиком в VRAM | — | ~23 |

То есть **20–25 ток/с достижимы размещением и битностью**, без единой новой оптимизации, и
это первая честная цель после 15.

### Почему пер-экспертный параллельный счёт оказался не тем, чем казался

Наш зонд намерил 86% перекрытия и рост экспертной стадии в 1.44 раза, и я называл это самым
крупным неподключённым выигрышем. Пересчёт с учётом стоимости пересечения границы устройств
это опровергает.

Пересечение мы измерили в 0.24 мс. Пер-экспертное разделение внутри слоя требует хотя бы
одного пересечения на слой, то есть 48 × 0.24 = 11.5 мс на токен, а если синхронизироваться
дважды — 23 мс. Выигрыш от того, что карта берёт свою долю экспертов, зависит от
резидентности: при нынешних 21% (3.19 ГБ из 15 при IQ4) он **отрицателен**, при 79% (то есть
с бонусом резидентным экспертам, который стоит 0.73% перплексии) он около 25 мс. Итого
чистыми +13 мс при одном пересечении на слой — то есть приём работает, но он не главный, и
работает только в связке с cache-conditional routing.

А вот выгрузка **целых слоёв** требует всего двух пересечений на токен, и потому даёт свои
проценты честно. Ровно поэтому прошлый замер `-ngl 36 -ot exps=CPU` провалился (8.01 против
8.7 на чистом процессоре): он резал граф 96 раз за токен, и 23 мс пересечений съели всё.

### Что остаётся для 40

Размещение и битность дают 20–25. Дальше нужен приём, уменьшающий байты ещё вдвое, и
единственный измеренный кандидат — разреженность активаций. У неё есть препятствие, которое
надо назвать прямо: **она требует своего ядра**.

Разреженность по выходной оси (строки `up` и `gate`) выражается существующими операциями, но
`gate` всё равно надо считать целиком, чтобы узнать разреженность, а `down` сжимается по оси
свёртки, где пропуск неконтигуален. Попытка обойтись `ggml_get_rows` разбивается об
усиление записи: собрать 384 строки `up` в f32 это 3 МБ записи против 417 КБ чтения, то есть
в семь раз хуже. Значит нужен GEMV с выбором строк по блочно-квантованным весам — правка
`iqk_mul_mat`, самая большая из всех, что мы делали. Один раз мы уже написали своё ядро под
мнимую проблему, поэтому здесь сначала замер выигрыша на заглушке, и только потом ядро.

### Почему перекрытие не достаётся из планировщика форка

У `ggml_backend_sched` есть флаг `parallel` и настоящий параллельный путь исполнения кусков
через OpenMP (`#pragma omp parallel num_threads(sched->n_backends)`). Но он закрыт двумя
условиями, и оба против нас.

Первое: путь включается только если `!has_cpu_work`, где `has_cpu_work` истинно, когда у
процессорного бэкенда **больше одного куска** графа. То есть параллелизм рассчитан на две
карты — ровно поэтому `--split-mode graph` отказывается работать меньше чем с двумя
устройствами.

Второе, более глубокое: барьер ставится перед любым куском, у которого есть входы
(`needs_barrier = split->n_inputs > 0`). Две ветви одного слоя MoE — резидентные эксперты на
карте и остальные на процессоре — обе зависят от одной и той же активации, значит у обеих
есть входы, значит обе за барьером. Перекрытия не будет даже если снять первое условие.

Вывод: перекрытие CPU и карты малой правкой планировщика не достаётся. Оно достаётся только
явно — пустить работу карты асинхронно, посчитать процессорную часть, синхронизироваться один
раз на слой, — и стоит 48 × 0.24 = 11.5 мс на токен. По бюджету байт выше это оправдано
только в связке с бонусом резидентным экспертам, который поднимает резидентность с 21% до
79% и стоит 0.73% перплексии.
