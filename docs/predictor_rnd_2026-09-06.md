# R&D предсказателя для НЕ-влезающих моделей (агент, 6 сент вечер)

## Факты (из заголовков GGUF/кода, не из доков)
- Coder-Next IQ4_XS: эксперт 1,391 MiB (gate IQ3_S 0,430 + up IQ3_S 0,430 + down IQ4_XS 0,531), 48 слоёв,
  пул 33,38 GiB (24 576). Трафик/токен = 480 × 1,391 = **668 MiB**. При C=330 (64,5%): резидентно 21,5 GiB,
  **overflow 182/слой = 11,9 GiB** (в STATE "9 GiB" — считалось по IQ3). C: 42,6 GB свободно →
  **весь overflow влезает на SSD, HDD-уровень не нужен**. SSD: 3,4 мс/эксперт, 0,41 GB/s ≈ 280 экспертов/с.
- Потолок при полной резидентности ≈ **125 мс/ток (8 tok/s)**; 2,62 tok/s = 381 мс → 256 мс — это диск.
- DeepSeek IQ2_XXS: ~8 MB/эксперт (оценка, уточнить по шардам 2-3), 240 × 8 = ~1,9 GB/токен.

## 1. Резидентность: частота остаётся, R1 НЕ рулит резидентностью
Измерено на 30B: hidden-state предсказатель проиграл LFU в 89 из 97 точек (резидентность спрашивает
"как часто", не "как скоро"). Decay/LRU ≤1,5 пункта. `L.score` кумулятивный — правильно. Что НЕ так:
- **P1 refresh() заливает синхронно** (expert_store.cpp:885-921, fill_slot :915-918) → каждый новый want
  = стойло 3,4 мс SSD/23 мс HDD на графовом потоке внутри end_token. На IQ3 один refresh = 334 копии =
  1373 мс (86 мс/ток амортизировано). ФИКС: ленивое продвижение — ставить want[id]=1, заливать при
  следующем реальном использовании (sync miss, который платили бы всё равно) в слот, защищённый pick_victim.
  Инвариант: ровно C id с want → ≥Z не-want слотов для жертв. Метрика: fills, ms_fill в ESTORE_AB.
- **P2 prior — рычаг резидентности.** expert_prior_coder_next.bin (4 сент) из 3 трейсов; сейчас 7+
  в D:\MemeX\results\dataset\*.trace.bin. Пересобрать (исключив eval-текст) — ноль правок движка;
  route_lab прогнозирует холодный старт 89,6→95-98% при 320-410.
- **P3 предсказатель→вытеснение (единственная здравая связь):** prefetch_expert (:1233) ставит
  touched=token_; расширить per-layer pred_tok[id], pick_victim пропускает предсказанных за 2-4 токена.
- **P4 тёплый SSD — снимок, не кэш.** prime() (:739-746) фиксирует по prior, build_warm (:791-883) пишет
  раз. Для Coder-Next (всё влезает) ок. Для DeepSeek (overflow > SSD) → slot-файл с LFU: на HDD-промахе
  I/O-worker пишет прочитанного эксперта в тёплый слот → повторные HDD-промахи станут SSD.

## 2. Глубина/горизонт префетча: ограничение — НЕ глубина, а ЧАСТОТА ВЫДАЧИ
Слой ≈2,6 мс, SSD-чтение 3,4 мс, I/O-worker (worker_main :1125-1150) однопоточный FIFO. K=4 = 10,4 мс
лида → ≤3 чтения успевают при пустой очереди. Правило: **≤0,7 SSD-чтений/слой (~34/токен)**.
Точность vs дистанция (hidden_lab, B=16): R1 k=1 96,8%, k=2 94,2%, k=4 90,2%; перенос k=4 86,2%.
Precision при B=16/10 истинных ≤62%; измерено used/issued 25% → **75% полосы префетча впустую**.
Фиксы: (a) гейт по МАРЖЕ скора (не ранг) под precision ≥60% — в do_prefetch (:1264-1306) заменить hi/lo
ранги на порог скора; (b) отменять устаревшие job (слой уже прошёл) + "украсть" не начатый job в do_map
(:624-634) синхронно вместо ожидания очереди; (c) два горизонта с РЕАЛЬНО обученными матрицами
(train_r1.py --k 8/12) вместо аппроксимации hdd_lead (memex-fwd.cpp:3807-3816); (d) кросс-токен: слои
0..3 (8% выборов) никогда не префетчатся (do_prefetch return при tgt<K :1246) — offline проверить
ridge H[t,47]→логиты слоёв 0..3 на t+1 и таблицу token_id→эксперты слоя 0.
HDD: 23 мс + 0,07 GB/s, 8 MB ≈ 70 мс ≈ 27 слоёв лида — недостижимо; префетч с HDD мерил 2,62→1,81.
**Никогда не префетчить с HDD внутри токена**, только миграция уровней (P4) ≤1 чтение/токен.

## 3. Бюджет полосы — честно
**Coder-Next IQ4_XS, весь overflow на SSD:** 3 tok/s = 333 мс → ≤61 sync-промахов. Нужен hit ≥87%.
Частота+prior при 64% резидентности даёт 95-98,5% (7-24 промаха → 150-207 мс → **4,8-6,7 tok/s**).
Холодный старт ~44 промаха/ток без префетча (2,5 tok/s) vs ~6 с ним. **Достижимо резидентностью;
R1 добавляет холодный старт и ~+0,5 tok/s.** В 381 мс есть ~110 мс необъяснённых (сверх 125+143) —
шаг 1 обязан разложить (ms_fill, fills, page faults).
**DeepSeek IQ2_XXS 89 GB:** ОЗУ 21 GiB ≈ 26% пула → 3 tok/s требует 95% hits при 26% резидентности —
недостижимо; реально 50-75% → **0,6-0,9 tok/s**. Даже 90% = 24×8 MB = 0,47 с → ≤1,7. Префетч не
спрячет: 20+ чтений × 22 мс ≫ 100 мс compute — SSD критический путь по ПОЛОСЕ. **Предсказание одно
DeepSeek не сделает юзабельным.** Путь: REAP-50% (45 GB → 52% резидентно → 85-93% → 1,2-2,2) +
1-бит холодные копии (½ байт промаха) → **2-3 tok/s, шатко**. REAP-k128 лучше полного 90 GB.

## 4. Mixed-precision холодные (HOBBIT)
Слоты — типизированные тензоры (init :351-353), низкобитная копия не разделит их. Добавить per-layer
gate_lo/up_lo/down_lo (IQ2_XXS/IQ1_S, Z_lo слотов) и второй mul_mat_id с разделёнными ids (паттерн
resident_split_ids, resident_set.hpp:298-315 — per-slot zero-add бит-точен). Lo-копии — второй тёплый
файл на SSD из низкоквант-GGUF той же геометрии (~5 GiB для Coder-Next overflow vs 11,9 hi). Выигрыш:
1,391→~0,77 MiB (−45%/промах, 3,4→~2 мс); DeepSeek 8→~4,9 MB. **МЕНЯЕТ ОТВЕТ** → именованный флаг
(--expert-store-repack-lo), верификация --decode-check + KL логитов. Не репаковать lo вместе с hi
(iqk_repack_tensor не идемпотентен, bulk_ :563-578).
