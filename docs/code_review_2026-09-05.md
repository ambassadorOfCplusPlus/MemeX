## Топ-5 серьёзных находок

1. **`GpuStatic::init()` разыменовывает `out` безусловно** (`gpu_static.cpp:311-333`) — прямое
   нарушение собственного комментария на :310, который разрешает `out==nullptr` при `head==false`
   (случай gemma4 «без головы»). Такой вызов даёт null-разыменование на :312. **Баг.**
2. **Пробник поддержки операций у экспертов проверяет только квант слоя 0**
   (`gpu_experts.cpp:878-915`). Модуль ровно про смешанный квант (комментарий hpp:404-419: слой 0
   q8_0, остальные q6_K). Тип, который Vulkan не умеет и который есть только на ненулевом слое,
   проходит init, а падает уже в середине прогона внутри `ggml_backend_graph_compute` — вместо
   ранней конкретной проверки. Обёрнуто в `try/catch` (громко), но это аборт на середине. **Баг.**
3. **hw_caps берёт VRAM/BAR у `devs[0]` без выбора типа устройства**
   (`hw_caps.cpp:124-133`). На ноутбуке с iGPU+дискретной картой или при наличии
   lavapipe/llvmpipe `devs[0]` может оказаться iGPU или программным устройством, которое отдаёт
   системную ОЗУ как device-local. Тогда весь смысл модуля (мерить нужную карту) теряется, а числа
   правдоподобны. **Баг** на затронутых машинах.
4. **Пробел учёта общего эксперта** (`expert_store.cpp:602-682`, `resident_set.hpp:56`). `do_map`
   обходит только маршрутизируемый `sel`; всегда-активный общий эксперт qwen3next не входит ни в
   `sync_misses`, ни в байты SSD/HDD, ни в знаменатель попаданий. 48 слоёв → 48 неучтённых чтений
   на токен. Отчётные «0,26 промаха/token» и суммы полосы диска систематически занижают реальный
   трафик; ёмкость планируется с ошибкой на одного всегда-активного эксперта на слой. **Риск**,
   прямо назван в HANDOFF §6 как условие включения набора.
5. **Тихий отказ вычисления карты** (`gpu_static.cpp:525, 888, 2477`): код возврата
   `ggml_backend_graph_compute` отбрасывается. Если Vulkan вернул `GGML_STATUS_FAILED` вместо
   исключения, `do_head`/`do_layer` читают устаревшие/нулевые данные, `fail_msg_` не ставится —
   провал неотличим от успеха. Ровно класс «правдоподобный мусор», от которого модуль защищается в
   других местах. **Риск (тихий отказ).**
