# Оптимизации от агентов (8 сент 2026) — ранжировано, по архам

Фанаут: агент на каждый арх проанализировал `build_*_step` в нашем движке. **Сходящийся вывод:
главный рычаг для ВСЕХ влезающих моделей — вынос статической половины на карту
(`--gpu-static-layers`), он ВЫКЛЮЧЕН ПО УМОЛЧАНИЮ и, вероятно, НЕ входил в пики 13.95/6.15.**
`MEMEX_FWD_GPU_EXPERTS` скомпилён в build-bt2022 → путь доступен без пересборки, нужна верификация
width-1 + замер, что влезает в 4 ГБ.

## Дешёвые победы (sibling-proven, стекаются, низкий риск) — делать первыми
- **qwen3moe `build_step`: `norm()`→`fnorm()`** (5 вызовов: 2462/2470/2474/2576/2758) — фьюз RMS-norm,
  gemma4/qwen35 уже так. Убирает 4 mul-узла/слой.
- **qwen3moe: фьюз up+gate** — `experts` лямбда (2617-2621) → `ggml_moe_up_gate(...SILU)`, как
  sibling `experts_g4` (3786-3790). −2 узла/слой ×48.
- **phi3: `norm`→`fnorm`** (2937/2986/3001) + **`ggml_fused_up_gate`** (сплит ВЕСА, не выхода, 2988-2994)
  + **`--repack-only=all`** (phi3 плотный, дефолт "experts" не репакует НИЧЕГО → идёт на плейн Q4_K
  вместо быстрого Q4_K_R4). Комбо +10-25% на 10.04.
- **gpt-oss: фьюз up+gate** `ggml_moe_up_gate_ext` (3117-3121), сверить OAI alpha=1.702. +3-8%.
> На чистом CPU (упор в DRAM-стену 24.8 ГБ/с, R²=0.998) фьюзы дают ~0.5-3%; их реальная цена — на
> card-пути (~27мкс/узел ×N слоёв). Поэтому главный приоритет — card-путь ниже.

## Главный рычаг — card-оффлоад (2-2.5× если карта тянет)

  только при width>1, к декоду не относится). → **~15-17 ток/с** (было 6.15).
- **gpt-oss**: голова ~600МБ на карту (`head_matmul`+`can_gstat`, 3133/4756/8058) → +25-30% → ~7.4;
  затем внимание+роутер+биасы+sinks (новый gpt-oss-блок в gpu_static.cpp) → ~8-9. Мой порт sinks = включатель.

## Не помогает / тупики (обосновано агентами)
- **Переквант gpt-oss MXFP4→Q4_K скорость декода НЕ поднимет**: декод упёрт в полосу (те же ~4.5 бита),
  а быстрый репак-путь только на prefill (nrc_y≥32). Меньший квант (Q3/Q2) — меньше байт, но −качество.
- **iqk repack экспертов** уже используется на CPU (mx1 13.38 = с репаком). В Vulkan _R4/_R8 нет.
- Delta-net/mrope/роутер-хвост — уже узло-минимальны, байты не двигают.

### КОРРЕКТИРОВКА прежних выводов (важно)
- **gpt-oss НЕ bandwidth-bound, а КОМПЬЮТ/ЯДРО-bound**: измерен ~45-55% своего byte-roofline (~1.9-2.5 ГБ/ток → roofline 10-13 ток/с, а идёт 5.7). Причина не байты, а МЕДЛЕННОЕ MXFP4-ядро.
  - **РЫЧАГ: MXFP4→MXFP4_R8 репак** — УЖЕ в форке (iqk_gemm_legacy_quants.cpp:8572 регистрация, iqk_quantize.cpp:5350 `repack_mxfp4` = чистый 8-строчный интерливинг, **0 изменения точности, те же 4.25 бита**, быстрое `mul_mat_qx_r8_q8_0`). Мой прежний вывод «репак не поднимет декод» БЫЛ ПРО Q4_K (верно), но пропустил R8. **Ожидание 5.7→~9-12 ток/с.** OOM был transient-mem гард (репак 11ГБ при резидентном mmap), не формат → офлайн MXFP4_R8 GGUF ИЛИ стриминг per-tensor репак (как ExpertStore).
  - Q4_K (4.5 бит) — ХУЖЕ (больше байт, ядро не быстрее). Q5/Q6 только под качество.
- **deepseek4 warm-тир СТАТИЧЕН** (`prime`/`build_warm` фиксируют warm_ids раз по частоте). HDD **seek-bound** (случайные 1-2МБ = ~23мс/промах) → **число промахов важнее байтов**.
  - **РЫЧАГ #1: динамич warm-промоушен** HDD→SSD по повторным промахам (счётчик в do_map:746, плюмбинг warm_base/fh_warm_pref_ уже есть). Повтор 23мс HDD → 2.7мс SSD (~8.5×). Ответ-сохраняющий.
  - **РЫЧАГ #2: макс warm-тир** (вместить хвост на SSD) — прямая атака на связывающее ограничение. Если хвост влезет → потолок 0.36→~2-4 ток/с.
  - MLA **подтверждён present+оптимален** (латентный KV, V из transpose, нет отдельного V-кеша). decode-only store guard на :3263 верен.
  - Предсказатель: **нулевой R1 = сломан** (все sc=0 → префетч [0..B-1] всегда). Identity R1 построен (top-B приближённого роутера). Обученная матрица — калибровкой.
